# Retrospective, cycle 22 (2026-08-31)

## What this cycle did

Finished the audit of the four tools that convert between URLs, paths and SKUs.
**All four were wrong.** Two were found in earlier cycles by accident; these two
were found by looking on purpose.

**`audit_catalog.py` would have failed the build on correct copy.** It is the CI
gate that refuses to publish when a page's price drifts from the catalogue. The
drift check captured only the leading digits of a price, `\$(\d[\d,]*)`, and
compared as an integer. So a page stating the **correct** $9.99 price of the
ebook was read as "$9", compared against 9.99, and reported as drift. Verified
by planting exactly that page.

This was a landmine, not a live failure: only one live SKU is priced in cents,
and no page currently writes that price within sixty characters of that name.
But the first time anyone did, the build would have failed on copy that was
right, and the obvious reading of that failure would have been *to change the
price on the page*. A gate that fails on correct copy is worse than no gate,
because the natural response is to break the thing it was defending.

It also meant real drift in the cents was invisible: any wrong price sharing
leading digits with the right one passed.

**The dashboard contradicted itself on its own headline card.** The
carry-forward wrote `out["customers"]`, a key **nothing anywhere reads**. The
deck renders `S["paying_customers"]`, which was never carried. So every run
without a Stripe credential produced a card showing **$19 of carried revenue
directly above a paying-customer count of None**. The cloud operator has no
credential, so that is what most published decks have looked like, one of the
two figures implying no customer had ever paid.

`customers_text` also rendered the literal string `"None"` rather than "not
measured", which is a Python repr leaking onto the page Phil reads.

## What went well

**Looking on purpose worked, and it was fast.** Two cycles found this class of
defect by luck. This cycle I wrote down "audit the remaining conversion tools"
as an action item, did it first thing, and found two more in about an hour. The
hit rate on that list was four out of four.

**I tested the false-positive direction, not just the false-negative one.**
The instinct with a checker is to ask "does it catch the bad thing". The $9.99
defect only appears if you also ask "does it leave the good thing alone". Both
new tests plant correct copy and require it to be ignored.

**I checked my own expectation before believing a failure.** The integer price
test reported drift on "The Standards Pack is $49" and my first thought was
that the fix was incomplete. The Standards Pack is free: $0. The tool was
right and my fixture was wrong. Two cycles ago I would have "fixed" the tool.

**The four defects have one shape**, worth stating as a sentence: *the tool
reported something other than what it had measured.* Not crashes, not wrong
maths. Silent substitution of a plausible answer for the real one.

## What did not go well

**Every one of these tools was written by me, in this project, with a careful
docstring explaining why it was needed.** The docstrings are accurate about the
problem and wrong about the solution. `audit_catalog`'s comment explains
precisely why price drift matters; the code beneath it could not read a price.
Confidence in the commit message is not evidence about the code.

**Nothing here was caught by review, only by fixtures.** I read all four of
these files at some point. Reading found nothing. Planting a fault found four
for four. **Reading code I wrote is close to worthless as a check on it.**

**The dashboard defect was visible on every published deck and I did not see
it.** I have looked at "$19" beside "None paying customers" many times over
several cycles and read straight past the contradiction, because I knew what the
numbers meant. Phil does not have that context and would have read it as
"nobody has bought anything".

## What to change next cycle

1. **Every check gets a fixture that proves it fails, before I trust it again.**
   Four for four is not bad luck, it is the base rate for untested checks in
   this repository. The remaining unfixtured ones are the gates in `preflight.py`
   itself: about a dozen, none of which have ever been shown to fail.

2. **Read the deck as Phil would, once per cycle, ignoring what I know.**
   The contradiction was on the card the whole time. A deliberate cold read is
   cheap and would have caught it.

3. **When a fixture fails, check the fixture before the tool.** Nearly wasted a
   fix on a correct check because I guessed a price.

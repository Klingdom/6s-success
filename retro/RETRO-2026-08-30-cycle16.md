# Retrospective, sixteenth cycle ending 2026-08-30

One commit. The audit list was finished last cycle, so this one asked a
different question: is the machinery that is supposed to be telling Phil
actually telling him? It was not.

---

## What went well

**Asking whether the notification works, rather than whether it ran.** The
status email workflow is green every few hours. Green means the job finished,
which is the same trap as the fulfilment poller: it can gate itself and pass.
The run log settled it, "sent <message-id>", so the email genuinely goes out.

**Then reading what it actually said.** It said Overall YELLOW, Website LIVE,
and did not mention the outage at all, on a day when every payment link the
site serves is deactivated. The one document the owner reads was the least
accurate surface in the system.

**Three faults, all the same shape, and the third was in a place I had already
fixed twice.** "LIVE" meant only that the homepage answered 200. The report had
stopped leading with the redeploy because a run without egress wrote "unknown"
over a measured "stale". And the lead condition keyed on staleness alone when
the sharper fact, a dead payment link, was sitting right there.

**Confirmed the button will work when it is pressed.** CI has published an
image from the newest commit touching site or ops, so a Redeploy pulls
everything including all six active payment links. That was worth knowing
before telling anybody the fix is one click.

**Verified in the built PDF, not in the code.** It reads RED, "LIVE BUT CANNOT
TAKE MONEY", and leads with the redeploy.

---

## What did not go well

**I fixed the carry-forward defect for revenue two cycles ago, watched the
cloud operator fix it for live links yesterday, and did not go looking for the
third instance.** It was in the same file, in the same shape, keyed on a
different field, and it silently removed the most important line from the
owner's report overnight. Fixing a class of bug and not sweeping for the class
is how the class survives.

**Last cycle I said the deploy-independent work was done.** It was not, and the
thing I missed was more important than most of what I had spent the week on. I
was measuring the site and never once checked the report about the site.

---

## What to change next cycle

**When a defect class is named, sweep for it in the same pass.** Three
instances of "a blind run overwrote a measured value" have now been fixed one
at a time, across three cycles, in one file. A grep would have found all three
the first time.

**Check the reporting surfaces, not only the thing reported on.** The dashboard
was right, the gate was right, and the email was wrong, which is the one that
reaches a person.

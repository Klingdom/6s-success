# Retrospective, cycle 36 (2026-08-31)

## What this cycle did

Claimed 5B.4 before starting it, then wrote the numbered on-device test script
so that Phil's five minutes with a QR code produce facts instead of impressions.

Twelve checks, each with the exact words to expect: the corpus reaching the
screen, the whole loop from draw to zone finish, progress surviving a restart,
airplane mode, screen reader announcement, web to mobile import, and Dynamic
Type at the largest setting.

## What went well

**Writing the script found two errors, which is the whole argument for writing
it.**

The first was mine. I wrote "tap Done once, then four more times" to finish a
zone. A zone is six passes and that is six taps. I caught it by simulating the
app's own rules against the real corpus rather than trusting the sentence I had
just written. An off-by-one in a test script is precisely the thing that would
waste the five minutes the script exists to protect.

The second was the app's. It read "1 of 114 zones in the house are holding",
which is the wrong verb for one zone, on the screen a person reaches at the
proudest moment in the product. It now says "is" when exactly one holds.

**The claim convention worked a second time.** One commit, pushed before any
work, and no collision.

**The script asks for failures in the exact words on screen.** Every line in it
is currently an assumption, so a failure is worth more than a pass, and the
document says that rather than implying everything will be fine.

## What did not go well

**I have now spent three cycles preparing for a five minute action I cannot
take.** The static ceiling is genuinely reached: bundling, corpus integrity,
merge rules, offline enforcement, accessibility semantics, and now the test
script itself. Everything remaining on the mobile app needs either a device or
an account. Preparing well is right; continuing to prepare would become
displacement activity.

**The grammar defect had been on screen since the app was written.** It survived
my own review, a bundle, an accessibility pass and a node simulation of the same
screen. It took writing down the exact expected words for a human to read before
I saw it. That is a useful lesson about which activities actually surface copy
defects: rendering and transcribing, not reviewing.

**Cycle fifteen, no revenue movement.** Day eight.

3. **Transcribe expected copy more often.** Two defects this fortnight were
   found by writing out what a screen should say, and none by reading the code
   that produces it.

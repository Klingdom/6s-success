# Retrospective, cycle 26 (2026-08-31)

## What this cycle did

Moved off gate hardening, as last cycle said to, and went at the product.

**The Home Quest now has a functional test, and it passes.** With every payment
link dead, the Quest is the whole of what the site delivers today: free, entirely
in the browser, no account, no payment. It had never been tested. Every check
here so far asks whether pages render, resolve, or say true things. **None asked
whether the product works.**

It works. Driven in a real browser at a phone width: a first time visitor gets
the first run screen; "Start at the door" opens a card in the Entryway door and
mat zone on the sort pass; the card names the zone, the pass, its purpose and
what to actually do; marking it done advances to a different card; progress is
written to storage; and a reload meets the returning visitor with their progress
header rather than the first run pitch again. That last part is the entire
premise of a quest you pick up over several days.

## What went well

**I checked two things before "fixing" them, and both were already right.**

The footer newsletter form looked inert: `onsubmit="return false"`, no `action`,
no `name` on the input. The obvious reading is a dead form silently swallowing
every signup, which would explain an email list of zero. It is not. It is wired
in JavaScript, deliberately, with an honest fallback: it tells the reader the
list is not connected yet and offers a one click mailto. The two blockers are
Listmonk instance settings, a `localhost:9000` root URL that makes every
opt in link unclickable and a from address belonging to another brand, both of
which sit behind a login I do not have.

And `/subscribe`, the sample PDF, the standards pack and the analytics script
all answer 200 live. So the non payment paths are intact.

**Verified the new test can fail** by renaming the done button's id: it reported
"the card has no way to mark it done" and "nothing was written to localStorage".

**I closed last cycle's runtime item with a measurement rather than a
restructure.** Preflight is 1m01s, of which the ten test files are 32.1s. The
two slowest are `audit_catalog` at 14.7s and `mobile_overflow` at 8.9s. That is
a reasonable price for what it buys, so it is accepted deliberately rather than
left unexamined. The item said "measure and budget, or accept the cost
deliberately. Right now it is neither." Now it is the second.

## What did not go well

**My own test had the exact defect I have spent a fortnight removing from
everything else.** Twice.

It cleared `localStorage` *after* the first load, by which point the page had
already read its saved progress and rendered the returning view; clearing
changed nothing on screen. **It passed the first time only because the browser
profile happened to be empty**, and failed the moment a previous run left
progress behind. And it used the default browser profile, so runs inherited each
other's state. A test whose result depends on something it did not set up is not
a test. Both fixed, and confirmed by running it twice in succession.

The uncomfortable part is that I wrote it while explicitly thinking about this
failure mode, in a file whose docstring is about honest measurement.

**Nothing this cycle moved revenue either.** The Quest is verified rather than
improved. Verification is worth something with traffic coming, but a fortnight
of green retrospectives should not read as progress toward $20k when the shop
still cannot take a payment.

## What to change next cycle

1. **Write the test's setup before its assertions.** Both defects were setup
   defects. I wrote what to check first and how to reach a known state second,
   which is the wrong order and produced an order dependent test twice.

2. **The Quest is verified but not improved. Improve it.** The obvious next
   question is what a visitor does after finishing a zone: whether the loop
   invites the next one, and whether finishing anything is acknowledged.

3. **Stop adding checks unless something is unchecked and valuable.** The
   coverage argument is close to exhausted. What remains untested is mostly
   things a customer never touches.

# Retrospective, cycle 24 (2026-08-31)

## What this cycle did

Set out to fixture `gate_generator_ownership`, the most expensive unchecked
gate, and found it had not been running at all. **Two independent things were
disabling it, and either one alone was enough.**

1. **It sits behind a `--own` flag.** CI runs plain `python3 ops/preflight.py`,
   so it ran there never. Locally it ran only when I remembered the flag, which
   across five cycles was once.
2. **Even with the flag, it skipped.** It refuses to run on a dirty tree, and
   `worktree_changes()` counts untracked files. `ops/shoot_mobile.py` writes a
   screenshot per page per width into `build/shots/`, which I never added to
   `.gitignore` when I built the harness five cycles ago. 84 untracked files,
   permanently dirty tree, permanent skip.

This is the gate guarding **issue #26: nine separate occasions** where a
generator was one run away from deleting content its own template does not
produce, every one caught by luck or by a diff someone happened to read.

**When it finally ran, it fired: 16 files.** The drift turned out to be the
opposite of what it usually catches. Nothing hand written was at risk. The
committed pages were stale, and the generators produce better content that had
never been regenerated. Three real fixes came out of it:

- `shop.html`'s Product structured data described the Entryway Deck as **"90
  cards"** while every visible line on the site says 88, which is what the deck
  is. Search and answer engines read the structured data, so we were publishing
  a wrong factual claim about a product we sell.
- The Organization schema on twelve pages was missing its logo.
- `404.html` referenced `measure.js` **with no fingerprint**, on a path served
  with a thirty day immutable cache. An unfingerprinted URL under `immutable`
  is precisely the bug that caching rule exists to prevent: an update to that
  file would never have reached anyone who had loaded the page.

## What went well

**Making the skip a failure paid for itself within one minute.** I changed the
"skipped" warning to a hard failure on the grounds that a gate you explicitly
asked for must not answer with something that reads like a pass. The very next
CI run failed and exposed an ordering defect the silent warning had been hiding
for as long as the gate had existed: preflight regenerates the command deck
early in its own run, so by the time it reaches this gate three of its own
artefacts are sitting modified in the tree.

**I checked the card count before believing it.** Six "90 cards" existed on the
site. Only one was wrong. The other five are the Mudroom and Moving Out decks,
which genuinely have 90. Two weeks ago I would have "fixed" all six.

**I checked nothing of mine was being reverted** before committing 16
regenerated files: the book cover fix and the invest table scroll container
both survive, and invest.html is not generator owned at all.

**The CI false alarm was diagnosed rather than silenced.** The gate's first
real run reported 110 zone pages as drift. They had not drifted:
`build_zone_pages.py` cannot reproduce its output without the source
photographs, which are gitignored, and their approval record is sha bound on
purpose so a verdict is worthless without the image it was given for. The easy
move was to drop the gate from CI again. Instead it now skips that one
generator where the photographs are absent, checks the other ten, and **says
which pages it could not cover, in both outcomes**.

## What did not go well

**I shipped half a fix and pushed it.** Excluding preflight's own deck output
from the dirty pre-check, verifying that, and not noticing the identical list
was consulted again forty lines later in the post-run comparison. The gate went
from "could not run" to "three files differ" and failed either way. One of two
places that consult the same list. The loud failure caught it, which is the
argument for the change that made it loud.

**I disabled a gate for five cycles by adding a feature.** The mobile harness
was good work. It also silently switched off the most expensive check in the
repository, and nothing connected the two. Adding an output directory is not an
obviously risky act, which is exactly why it went unnoticed.

**I have been reading `preflight | tail -3` for weeks.** The skip warning was
printed on every run. It sat above the three standing warnings and my own habit
of truncating the output cut it off. The tool was telling me and I had arranged
not to hear it.

## What to change next cycle

1. **Never truncate a gate report again.** Read the whole warning block. The
   information was there the entire time.

2. **When adding anything that writes files, check `git status` afterwards and
   gitignore it in the same commit.** This one cost five cycles of a dead gate.

3. **When fixing a shared value, grep for every consumer before pushing.** Third
   time this month the lesson is "one instance is not the class", and the first
   time it has cost a red CI run.

4. **Fixture the gate now that it runs.** That was this cycle's actual goal and
   it is not done: the gate has never been shown to fail on a planted hand edit,
   only on real drift it happened to find.

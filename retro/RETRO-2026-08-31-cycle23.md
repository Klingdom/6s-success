# Retrospective, cycle 23 (2026-08-31)

## What this cycle did

Started fixturing the gates inside `preflight.py`, the last unchecked checks in
the repository. Six now prove they can fail: third-party requests, unsourced
statistics, stale claims, bundle maths, a page missing from the sitemap, and an
unresolved conflict marker.

The rule each one is now held to is two questions rather than one:

    with a fault planted, does it complain?
    with the fault removed, does it stay quiet?

Only the second is true today, and only the second is what a passing run tells
you. That is the whole reason four analysis tools were found broken this week
while every one of them reported "clean".

**One real gap closed.** `gate_bundle_maths` only scanned `site/*.html`, the
seventeen files sitting directly in `site/`. It never saw the 170 zone, room and
article pages. That exact glob has already been found too narrow twice in this
repository, both times in the dashboard, where it skipped those same pages and
reported "not scanned" as zero. No subdirectory page states a saving today, so
nothing was wrong on the site, but a price claim on a zone page would have been
exactly as wrong and exactly as unchecked.

## What went well

**The harness found a flaw in my own test design within minutes of existing.**
`stale-claims` cannot be tested by asking whether it fires, because it has two
legitimate standing hits that are real page copy and still true: the WCAG
statement of intent, and the note that no paid reset day has been run. A gate
with a correct non-zero baseline needs its *count* compared, not its silence.
I had written the naive assertion and the harness rejected it immediately.

**Both directions, deliberately.** For `bundle_maths` especially: a wrong saving
must be caught, and the **correct** saving must be left alone. "Save $17" and
"bought separately they are $66" were both true until the ebook moved from $18
to $9.99. A gate that rejected the true number would push someone to write a
false one onto a page that takes money. This is the same failure mode as
yesterday's price check that would have failed the build on correct copy, and I
went looking for it this time rather than tripping over it.

**Calling gates directly rather than through `main()`** keeps the suite fast and
makes a failure name the gate rather than say "preflight failed".

**I checked before believing the worst.** A stash pop left the three generated
files in an unresolved index state right after a push. Given that a rebase once
put conflict markers into `preflight.py` and silently killed every gate in it,
that looked alarming. I checked the committed blobs, the working copies, and ran
the conflict-marker gate itself: nothing corrupt anywhere, just leftover index
state. Two cycles ago I would have panicked or, worse, forced something.

## What did not go well

**Six of twenty-seven.** I have fixtured the gates that a single planted HTML
file can trigger. Twenty-one remain, including `gate_generator_ownership`, which
exists to stop a generator deleting hand-written work, and the four dashboard
carry-forward gates. Those need more setup and I stopped at the cheap ones. The
honest summary is that this is a start, not a finish, and the unfixtured
majority still has a measured defect rate of four for four.

**A heredoc ate a backslash again**, turning `\n` inside a string into a real
newline and producing a syntax error in the test file. Fifth instance this week.
I keep reaching for the heredoc because it is one line shorter than writing a
file, and I keep paying for it. This time it failed loudly, which is the good
version of the failure, but three of the five have failed silently.

**I did not widen the glob everywhere it is narrow.** I fixed
`gate_bundle_maths` and did not grep for the other places that still glob
`site/*.html`. That is the exact lesson from two cycles ago, written down and
then not applied. Naming an assumption is not the same as searching for it.

## What to change next cycle

1. **Grep for `site/*.html` and widen every instance, or record why each one is
   deliberately narrow.** Three found wrong so far. Do the search this time
   instead of writing it down again.

2. **Fixture `gate_generator_ownership` next.** It protects hand-written work
   from being overwritten by a generator, which is the most expensive thing on
   the unfixtured list if it has quietly stopped working.

3. **Stop using heredocs for anything containing a backslash.** Not a
   preference: a rule, with five instances behind it.

## Addendum: acting on item 1 inside the cycle, again

Item 1 said to grep for `site/*.html` rather than write the lesson down a third
time. **One grep found three more gates with the narrow glob**, all of them
checking public copy and none of them ever looking at the 166 zone, room and
article pages:

- `gate_unsourced_stats`, which enforces the rule against fabricated statistics
- `gate_copy_vs_control`, which checks a price written in prose against the
  catalogue, and the most valuable of the three because zone pages carry product
  packs with prices
- `gate_stale_claims`, which catches copy that rots

**I measured before changing anything**: 166 unscanned pages, and **zero actual
hits** among them. So these were latent gaps, not live faults, exactly like the
bundle maths gate earlier in the same cycle. Nothing was wrong on the site.

That measurement is the part worth keeping. The tempting write-up is "found
three more defects"; the true one is "found three more blind spots, none of
which anything had fallen into yet". Overstating this would make the next
retrospective less trustworthy, including to me.

Widened anyway, because the cost is one line each and this glob has now been
found too narrow **four times**: twice in the dashboard, where "not scanned" was
reported to Phil as zero, and twice today. And verified afterwards that none of
the three fires on the current site, so no false positive was introduced that
could block a deploy, which is the failure mode I walked into yesterday with the
price check.

They now share one `all_pages()` helper, so the next check that needs the public
surface has something obvious to call instead of a fifth copy of the wrong glob.
**That is the actual fix.** The four previous instances were each corrected in
place, which is why there was a fifth, sixth and seventh.

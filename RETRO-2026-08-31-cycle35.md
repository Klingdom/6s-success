# Retrospective, cycle 35 (2026-08-31)

## What this cycle did

Claimed a backlog item before working it, which is the fix for yesterday's
collision, then did the half of mobile accessibility that needs no device.

The claim came first and was pushed on its own, before any work, so the cloud
operator could see it inside a minute. That convention is now written into the
backlog rather than living in my head.

## What went well

**Measuring first meant two of three expected fixes turned out to be unneeded.**

  contrast   all 12 foreground and background pairs pass. Body text 12.11:1
             against a 4.5 requirement, weakest pass badge 3.04:1 against 3.0.
             Computed, not eyeballed.
  targets    primary button about 49 points, ghost about 43, against a WCAG 2.2
             minimum of 24.
  scaling    React Native honours Dynamic Type by default, so the correct action
             was to add nothing.

Had I started from the assumption that a hand written app must have poor
accessibility, I would have "fixed" a palette that was already right. The web
app's accessibility work carried over because the app inherited its colours.

**The real gap was semantics, and it was total.** Five interactive elements, zero
accessibility properties between them. A screen reader user reached a control
and heard its text with nothing to say it could be activated. Six controls now
carry a role, a label and a hint, and the decorative colour dots are hidden,
which is the same decision the web app made for the same reason.

**The offline promise is now enforced rather than stated.** The principles say
local-first because garages are core terrain, and that photographs of home
interiors must never leave the device. Nothing checked it. Adding a sync call is
a two line change that would pass any review. The new test fails on any fetch,
XMLHttpRequest, WebSocket, sendBeacon, FormData or outbound URL in app source.

**It strips comments before searching, deliberately.** A comment explaining that
there is no network call must not be read as one. That is precisely the mistake
I made about photos.js a few cycles ago, and building it into the checker is
cheaper than remembering.

## What did not go well

**"Accessibility checked" is a claim I cannot make and nearly implied.** What is
checked is contrast, target size, roles, labels and decorative hiding, all
decidable from source. Announcement order, focus movement and gesture
alternatives need a real screen reader on a real phone. The backlog row says so
in those words rather than showing 5B.9 as done.

**Everything this cycle is still one QR scan away from being real.** The loop,
the import picker and the screen reader behaviour are all "probably". Five
minutes of Phil's time converts three probablies into facts, and I have now
listed that ask for three cycles running.

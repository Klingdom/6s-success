# Retrospective, cycle ending 2026-08-30

Nine commits. Every one of them downstream of the same discovery: I published
114 pictures without looking at them.

---

## What went well

**The gate caught the thing the reviewer would have caught.** Not the image
review, which I had to invent halfway through the cycle. The generator
ownership gate, written weeks ago after `build_resources.py` nearly deleted
the links to 134 pages, fired on its ninth data point and stopped a stale
service worker shipping. My CSS change moved `site.css`'s fingerprint, and
`sw.js` still precached the old hash. Offline that is a real outage: the fetch
handler matches on exact URL, so a stale precached hash never matches and the
asset falls through to network, which is the one thing that does not work in
the garage the feature exists for. Nobody noticed it. A gate did.

**Fixing the prompt beat reviewing the batch.** After twenty four images the
pass rate was near half, and the tempting move was to keep grading. Diagnosing
instead took one look at the prompt builder: the zone name never reached the
model at all. Only the `done_looks_like` sentence was sent, and those sentences
are standards rather than descriptions, "five things or fewer", "a hand's width
of empty space". There is nothing there to draw. Pass rate went 46 to 72
percent for ten minutes of GPU time, and the twelve zones still failing are
failing for a reason I can name rather than a reason I am guessing at.

**Writing 32 subjects by hand was the right call, not a defeat.** The zones that
kept failing share a property: their standard names a rule or a place, never a
thing. No amount of prompt assembly extracts an object from "paper and
household backstock" because the object is not in the source. Twenty of the 32
passed on the next attempt. The garage wall came back as an actual pegboard of
hand tools instead of a room of sawhorses.

**Two false alarms found and killed.** The ownership gate reported 186 files as
drift on a tree where `git diff` was empty and `git add -A` staged nothing at
all: `git status --porcelain` calls a file modified as soon as its mtime moves,
and the gate reruns eleven generators over 189 pages. It had passed an hour
earlier only because a commit had just refreshed the index. Separately, the
dashboard printed "GitHub unreachable" on a machine where `gh` was logged in
and a push had succeeded seconds before. Nothing had asked; it only read env
vars. Both are the same defect wearing different clothes, and it is the one
this repository has now hit four times: **a check that reports "I found
nothing" when what happened was "I did not look."**

## What did not go well

**I wired 114 unreviewed images onto 114 live pages.** They sat there through a
full rebuild, an audit and a fingerprint pass before I looked at one. When I
did, the second image I opened was a garage tool wall rendered as sawhorses and
lumber, and the board game zone was a stack of moving boxes. Every one carried
a caption reading "an illustration of the finished state". That caption is a
claim about the picture, and for those it was false. CLAUDE.md section 8 forbids
fabricated before and after results; arriving there by carelessness rather than
intent does not make the page any more honest to the person reading it.

**The failure was ordinary and predictable.** Generation reported "114 of 114 in
13 minutes" and I treated a success count as a quality signal. The pipeline had
a `verify()` step, and it passed everything, because it checks that an image is
not blank or corrupt. Nothing in it could tell a tool wall from a sawhorse.
I knew that when I wrote it.

**I asserted a verification I had not run.** The commit message for the gate fix
said "verified both ways: clean tree passes, and a real hand edit still fails
it." I had only run the first half. I went back and ran the second, and it does
fail correctly on exactly the one edited file, but the sentence was true only
after I checked, not when I wrote it.

**Three cheap defects shipped inside otherwise careful work.** `.zone-hero` had
no CSS at all, so 114 images rendered unstyled. The alt text read generation
syntax, "warm wood and painted wall, daylight", aloud to screen readers. And
the new dashboard chip used a CSS class the stylesheet does not define. All
three were found by looking at output rather than at code, which is the same
lesson as the images, at a smaller size.

## What to change next cycle

**Generated content is unpublished until something with eyes approves it.**
Now enforced rather than intended: `ops/review_heroes.py` builds contact sheets,
twelve to a page, so 114 images take ten looks. `ops/wire_zone_heroes.py` wires
only approved stems, and unjudged counts as rejected, because at the moment of
wiring an image nobody looked at and one that failed are indistinguishable.

**A verdict is about one picture, and dies with it.** Each verdict records the
sha of the image it was about. Regenerating a zone puts different pixels at the
same path, and a carried over approval would publish something nobody has seen
while reporting it reviewed. That is this cycle's own failure sneaking back in
through the door I had just built. Verified by regenerating 32 and watching
exactly those 32 drop back to unjudged.

**Stop letting an absent answer read as a clean one.** Fourth occurrence now.
Every check that can fail to look must say so distinctly from finding nothing,
and both gates fixed this cycle now do. The next one written should have that
property before it is merged, not after it misleads somebody.

**Extend the review gate to the rest of the image work.** The card decks, the
before and after pairs and the chapter figures all run through generators with
no equivalent gate. The zone heroes were not special; they were just first.

## 1. Naming conflict, resolved 2026-08-25

The source contained **two different documents both named EXECUTIVE-DASHBOARD**. They were not
versions of each other. Neither was a superset: 133 headings versus 140, with genuinely different
content.

- `EXECUTIVE-DASHBOARD.md` (installed at project root) covers Claude Current Mission, Executive
  Action Buttons, Global Pause, Drill-Down Pages, Dashboard Data Contract, Current Dashboard State.
- `EXECUTIVE-DASHBOARD-ALT.md` (was parked here as `EXECUTIVE-DASHBOARD(1).md`) covered Revenue Mix,
  Revenue Definition, Customer Outcome Definition, Qualified Visitor Definition, Conversion
  Definition, Experiment Guardrails.

**Resolved:** root `EXECUTIVE-DASHBOARD.md` kept as canonical, `EXECUTIVE-DASHBOARD-ALT.md`
discarded. It is every other control doc's existing reference target, and ALT's
once-unique sections are now redundant with `METRICS.md` (Funnel Conversion Definitions,
Experiment Guardrail Breach) and `CUSTOMER-JOURNEY.md` (Qualified Visitor), both written after
this install. Full reasoning in `DECISIONS.md` D-002. Closes issue #8. The discarded file's
content remains in git history prior to this commit if ever needed again.

## 2. Fifteen referenced documents do not exist

The installed docs reference 54 control documents by name in backticks. 39 are present. These 15
are referenced but were not in the source folder:

```
ARCHITECTURE.md        CONTENT.md          GROWTH-PLAYBOOK.md
BACKUP-RESTORE.md      DAILY-LOOP.md       INCIDENTS.md

CONTENT-STANDARDS.md   SEO-AEO.md          ROADMAP.md
```

This is not necessarily a fault. Some may be planned rather than written, and some may be intended
to be generated by the system itself as it runs. But any agent instructed to read one of them will
find nothing, so it is worth knowing which are deliberate and which are missing.

Note `SEO-AEO.md` is referenced as a control document while `seo-aeo` also exists as an agent. Those
are different things and the reference may be a mistake.

## 3. Scope note

The agents are installed at **project scope**, so they load when Claude Code runs with
`C:\Users\philk\6s-success` as the working directory. They will not load from another folder.

This matters because most 6S source material lives elsewhere: the book master is under
`Desktop\Process Kaizen\...\Master\6S Success Home Edition\`, and the products are under
`Desktop\6S-*\`. The agents can still read those paths, but they only exist as agents when the
session starts here.

If they should be available everywhere, they can be copied to `C:\Users\philk\.claude\agents\`
instead. Do not put them in both places.

## 4. Context cost

`CLAUDE.md` is about 24 KB and loads into context on every session in this directory. That is
workable but not free. If sessions start feeling short on context, the first thing to try is
moving the reference-heavy sections of `CLAUDE.md` into a document it points to, keeping only
standing rules in `CLAUDE.md` itself.

# Retrospective, cycle 25 (2026-08-31)

## What this cycle did

Finished cycle 24's actual goal, which that cycle had named and not done:
**`gate_generator_ownership` now proves it catches a hand edit.** Until today it
had only ever been seen firing on drift it happened to stumble into, and for
five cycles before that it had not been running at all.

Testing it is awkward, because it refuses to run on a dirty tree, so the edit
has to be **committed** before the gate can see it, and committing on the real
branch to test a check is not acceptable. It uses a detached git worktree
instead: a second checkout sharing the same object database, where a commit is
free and throwing the whole thing away costs nothing. Two assertions, the second
mattering as much as the first: a hand edit to a generated page is reported **by
name**, and an untouched checkout is **not** reported. Without the second, a
gate that failed on everything would pass.

Verified in CI, where it runs in 58 seconds and reported the planted edit
correctly.

## What went well

**I checked the fixture before believing the failure.** The first version
targeted `site/about.html`, and the gate did not report the edit. Read one way
that is "the gate is broken". It was not. `about.html` is a hand written page
whose *head blocks* are wired in by generators; its body is nobody's output and
survives a build untouched, which is exactly correct behaviour. I proved it by
planting a marker in three pages and running the generators over them:
`about.html` kept it, `resources.html` and `zones/index.html` did not.

Picking a target for a test like this is a claim about ownership, and it needed
checking like one. This is the third cycle running where the first apparent
defect was in my own fixture, and the second where checking first saved a wrong
"fix" to working code.

**I found and closed an unbounded recursion.** This test drives `preflight`, and
preflight's `gate_tests` runs this test. That recurses without limit. It
terminated during development only because creating a worktree *inside* a
worktree happened to fail, which is an accident of the filesystem, not a
control. `gate_tests` now marks its children and the test declines and says why,
so it runs exactly once in CI: in the dedicated test step, not underneath
preflight.

**The honesty pattern is visibly holding.** The same CI log shows the mobile
probe reporting `NOT VERIFIED` because there is no browser on the runner, rather
than reporting clean. That is the behaviour this fortnight has been spent
building, appearing without me having to think about it.

## What did not go well

**I nearly shipped an infinite loop into the thing that runs every other
check.** The recursion existed the moment I wrote the test, and the only reason
I noticed is that I stopped to ask why a 2m33s run had terminated at all. If
worktree nesting had happened to succeed, `preflight` would have hung on every
invocation, locally and in CI, and the failure would have looked like a timeout
rather than a bug.

**Preflight is now 1m13s, up from about 15s two weeks ago.** Every test I add
lands inside `gate_tests` and slows the thing I run several times a cycle. None
of the individual additions was wrong, and I have not once measured the total.
That is how a check budget gets spent without a decision being made.

**Nothing this cycle moved revenue.** Two weeks of correctness work with the
shop unable to take a payment throughout. That is the right order given a broken
deploy is the constraint, and it is worth writing down plainly rather than
letting a run of green retrospectives imply progress toward the goal.

## What to change next cycle

1. **Measure and budget preflight's runtime.** Split the slow tests out of
   `gate_tests` into something CI runs and a local preflight does not, or accept
   the cost deliberately. Right now it is neither.

2. **Before writing a test that invokes a runner, ask what runs the test.**
   Cheap question, would have caught the recursion at design time.

3. **Next cycle goes to something a customer would notice.** The gates are in
   good shape. The unfixtured majority is now the minority, and further
   hardening has diminishing returns against a site nobody can buy from.

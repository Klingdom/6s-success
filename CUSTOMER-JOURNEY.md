# 6S Success Customer Journey

> Canonical customer-experience architecture for 6S-success.com, connecting discovery, personal values, desired room and micro-zone functions, root-cause diagnosis, quests, cards, solutions, products, purchases, implementation, sustainment, repeat use, and whole-home progression.

## 1. Purpose

`CUSTOMER-JOURNEY.md` defines the experience every 6S Success agent should collectively improve.

The primary journey is:

**Discover**
→ **Understand**
→ **Choose an Area**
→ **Define Desired Function**
→ **Diagnose Root Cause**
→ **Choose Outcome**
→ **Start a Quest**
→ **Complete Cards**
→ **Use / DIY / Buy**
→ **Complete the Reset**
→ **Verify the Outcome**
→ **Sustain**
→ **Choose the Next Micro-Zone**
→ **Progress Through the Home**

This journey should work across:

- website
- smartphone app
- digital decks
- physical decks
- QR codes
- SEO/AEO content
- social content
- email
- products
- kits
- services
- multiplayer quests

# 2. Prime Experience Rule

**Help the customer make one area noticeably easier to live with as quickly as possible.**

Do not force customers to understand Lean, 6S terminology, a complex taxonomy, or the entire platform before receiving value.

---

# 3. Customer Promise

The experience should help a person answer:

1. What do I want this area to do?
2. What is getting in the way?
3. What is the smallest useful improvement I can make?
4. What should I do first?
5. What do I need?
6. How will I know it worked?
7. How do I keep it working?

---

# 4. Journey Philosophy

6S Success should feel like:

**A helpful guide + a game + a practical operating system for the home.**

It should not feel like:

- a lecture
- a generic organizing blog
- a product catalog
- a long audit
- an endless checklist
- a guilt-based cleaning system

---

# 5. Primary Customer Outcome

The customer should leave a session with:

- less friction
- clearer function
- visible progress
- a completed micro-zone or meaningful step
- confidence about what comes next

# 8. Search Entry

Example:

> "How do I stop shoes piling up by the front door?"

Ideal path:

```text
Useful direct answer
→ Entryway shoe micro-zone
→ quick diagnosis
→ desired outcome
→ 15-minute quest
→ optional solution
```

Do not force the visitor through the homepage first.

---

# 9. AI/AEO Entry

Pages should answer the question clearly enough to be useful even before conversion.

Then offer the next action:

> Fix this micro-zone in 15 minutes.

The CTA should extend the answer rather than gate it.

---

# 10. Social Entry

Social posts may lead directly to:

- one card
- one micro-zone
- one challenge
- one before/after
- one desired-function question

Keep continuity between the social promise and landing experience.

---

# 11. QR Card Entry

A QR code from a physical card should open the exact card or quest context.

Avoid:

```text
Card QR → Homepage → Navigation → Search → Card
```

Prefer:

```text
Card QR → Card Detail / Active Quest
```

---

# 12. Product Entry

A visitor arriving on a product page should still understand:

- what problem the product solves
- which micro-zone it fits
- what desired function it supports
- whether a no-purchase alternative exists
- how it fits into a quest

---

# 13. First-Visit Experience

Within the first meaningful interaction, the visitor should understand:

- what 6S Success helps with
- that improvements can be small
- where to begin
- that personalization is possible

Avoid overwhelming them with the whole-home system.

---

# 14. Homepage Primary Job

The homepage should quickly help a visitor choose one of a small number of useful paths.

Potential:

**Fix a Room**
**Solve a Specific Problem**
**Start a Quick Quest**
**Explore the Entryway Deck**

Do not create excessive competing CTAs.

---

# 15. Problem-First Path

Some users think in problems, not rooms.

Examples:

- I can never find my keys
- shoes pile up
- mail covers the counter
- bathroom drawers are chaotic
- laundry never gets put away

Support problem-first navigation.

---

# 16. Room-First Path

Other users know the room they want to improve.

Example:

```text
Entryway
→ choose micro-zone
→ desired function
→ diagnosis
→ quest
```

---

# 17. Time-First Path

Some users only know how much time they have.

Support:

- 15-minute quest
- 30-minute quest
- 45-minute quest
- 60-minute quest
- 90-minute quest

Then match high-value activities to available time.

---

# 18. Card-First Path

Physical deck users may start with a card.

The digital system should recognize the card and provide:

- instructions
- timer
- examples
- related cards
- optional products
- completion tracking

---

# 19. Multiplayer Path

For 1–10 players:

```text
Create/Join Quest
→ choose room/micro-zone
→ select duration
→ assign/draw/volunteer for cards
→ complete in parallel
→ reveal progress
→ final reset/check
→ celebrate outcome
```

The experience should reward cooperation, not create household conflict.

# 20. Personal Values Discovery

Personal values help define what "better" means.

Potential values:

- speed
- calm
- simplicity
- beauty
- safety
- independence
- accessibility
- preparedness
- hospitality
- minimalism
- cleanliness
- sustainability

Do not require a long personality assessment.

---

# 21. Values Question

Example:

> What matters most when this area is working well?

Allow a small number of selections.

Examples:

- I can find things immediately.
- Everyone knows where things go.
- It looks calm and uncluttered.
- It is easy for children to use.
- It is safer and easier to move through.
- It takes almost no effort to reset.

---

# 22. Desired Primary Function

Ask:

> What is the most important job this area should do for you?

This is more useful than:

> How should this area be organized?

---

# 23. Function Suggestions

Suggestions should be contextual.

Entryway examples:

- fast departure
- easy arrival/reset
- family launch zone
- guest-ready welcome
- safe shoe/coat storage
- child-independent routine
- accessible seating and storage
- incoming/outgoing staging

Allow custom input when needed.

---

# 24. Function Conflict

A micro-zone may be trying to perform too many functions.

Example:

Entryway console is simultaneously:

- key storage
- mail processing
- charging
- decoration
- returns staging
- child school-paper storage

The system should identify function conflict as a possible root cause.

---

# 25. Root-Cause Diagnosis

Do not jump from:

> "My entryway is messy"

to:

> "Buy bins."

Diagnose likely causes.

Common patterns:

- too many items
- no dedicated home
- storage too far away
- insufficient capacity
- poor visibility
- difficult access
- unclear ownership
- mixed functions
- missing reset routine
- wrong container
- behavior/system mismatch

---

# 26. Diagnostic Question Design

Questions should be:

- short
- observable
- actionable
- nonjudgmental
- specific to the micro-zone

Avoid unnecessary surveys.

---

# 27. Adaptive Diagnosis

Do not ask every possible question.

Use answers to narrow the next question.

Example:

```text
Do keys usually land in the same place?
   ↓ YES
Is that location where you want them?
   ↓ YES
Do they still become difficult to find?
   ↓ YES
Likely issue: unclear visual home / mixed items
```

---

# 28. Diagnosis Output

Provide:

## Desired Function

What the customer wants.

## Likely Root Cause

What appears to create friction.

## Target Outcome

What "fixed" should look like.

## Recommended Quest

Smallest useful action.

---

# 29. Confidence

If diagnosis is uncertain, say so.

Potential:

```yaml
diagnosis_confidence: HIGH|MEDIUM|LOW
```

Low confidence should lead to another question or observation.

---

# 30. Desired Outcome

Outcome should be specific enough to test.

Example:

> Each family member has one clearly marked shoe location near the normal entry path, with only currently used shoes stored there.

---

# 31. Quest Selection

Quest recommendation should consider:

- root cause
- desired outcome
- available time
- number of players
- available supplies
- difficulty
- safety
- dependencies

---

# 32. Quest Preview

Before starting, show:

- objective
- estimated time
- number of cards
- supplies
- players
- expected result

Keep it compact.

---

# 33. Quest Start

Starting should require minimal friction.

Avoid mandatory account creation before the first useful quest unless technically necessary.

Consider allowing progress before registration and offering save/sync later.

---

# 34. Card Selection Modes

Potential modes:

- preconfigured
- random
- by micro-zone
- by 6S activity
- player choice
- assigned by host
- difficulty-based
- time-based
- adaptive

# 35. Card Experience

Each card should clearly show:

- action
- location
- why it matters
- estimated time
- success condition

Optional:

- timer
- photo example
- tip
- product/tool
- QR/digital support

---

# 36. Card Completion

Completion should be satisfying but quick.

Potential:

- tap complete
- swipe
- photo
- teammate confirmation
- automatic quest progression

Do not make documentation harder than the improvement.

---

# 37. Blocked Card

Allow:

- skip
- replace
- need supplies
- not applicable
- ask for help

A blocked card should not kill the quest.

---

# 38. Dynamic Quest Adjustment

If a card reveals a root cause, the system may adapt.

Example:

Customer tries to organize 20 pairs of shoes into a six-pair zone.

System may introduce a Sort card before recommending more storage.

---

# 39. Product Recommendation Moment

Only recommend products when the quest identifies a genuine solution need.

Use the structure in `PRODUCT-CATALOG.md`.

---

# 40. Solution Choice

When relevant, present:

**Use What You Have**
**DIY / Print**
**Buy a Ready-Made Solution**

This reinforces trust and accommodates different budgets.

---

# 41. Purchase Journey

If the customer chooses Buy:

```text
Recommendation
→ Why it fits
→ Compatibility
→ Price
→ Product Detail
→ Cart
→ Checkout
→ Confirmation
→ Return to Quest
```

Do not strand the customer in commerce.

---

# 42. Post-Purchase Return Path

After checkout:

> Continue your Entryway Key Landing Quest.

Preserve quest state.

---

# 43. Waiting-for-Product State

If the product is required before completion:

- save quest
- mark blocked/waiting
- provide any preparatory cards
- resume later

Do not falsely mark quest complete.

---

# 44. Digital Product Delivery

Digital products should return the customer directly to value.

Examples:

- open deck
- download printable
- launch quest
- open reset manual

Avoid confusing fulfillment.

---

# 45. Quest Completion

At completion, show:

- what changed
- cards completed
- time
- outcome
- optional before/after
- sustainment action
- next recommendation

Celebrate progress without excessive gamification.

---

# 46. Outcome Check

Ask a simple question such as:

> Is this area now easier to use for the function you chose?

Potential:

- Yes
- Partly
- No

Then adapt.

---

# 47. If Outcome = Yes

Proceed to:

- standard
- sustain
- next micro-zone
- optional sharing

---

# 48. If Outcome = Partly

Ask what remains.

Potential:

- too many items
- still hard to find
- storage does not fit
- family not using system
- need another product/input
- not enough time

Recommend targeted follow-up.

---

# 49. If Outcome = No

Do not immediately sell another product.

Revisit:

- desired function
- root cause
- solution fit
- compatibility
- quest execution

A failed outcome is learning.

---

# 50. Standardize

Once the area works, help define the standard.

Examples:

- where items live
- maximum quantity
- labels
- photo standard
- ownership
- replenishment level

---

# 51. Sustain

Sustainment should be lightweight.

Potential:

- 30-second reset
- weekly card
- visual standard
- min/max consumable
- recurring quest
- household responsibility

---

# 52. Visual Standard

A completed micro-zone may capture a photo of the desired state.

This can become a personalized reset reference.

Respect privacy and storage policy.

---

# 53. Next-Best Quest

Recommend the next activity based on:

1. adjacent friction
2. customer goal
3. available time
4. prior success
5. room progression

Do not always recommend the most expensive next step.

---

# 54. Room Completion

A room can progress through multiple micro-zones.

Show:

- completed
- stable
- needs attention
- not applicable

Avoid implying a home must be perfect.

# 62. Gamification Principle

Game mechanics should increase:

- initiation
- focus
- cooperation
- completion
- repeat participation

If a mechanic reduces real-world completion, remove it.

# 63. Progress

Measure meaningful progress, not meaningless points.

Examples:

- micro-zones reset
- quests completed
- standards sustained
- friction reduced
- time saved

# 64. Streaks

Avoid punitive streak mechanics.

Missing a day should not make the customer feel they failed.

Prefer:

> Welcome back. Pick up where you left off.

# 65. Notifications

Notifications should support real actions.

Examples:

- resume blocked quest
- product arrived
- quick weekly reset
- consumable below minimum

# 72. Support Journey

- product does not fit
- quest is confusing
- order has an issue
- account access fails

# 73. Accessibility

The journey should consider:

- mobility
- reach
- vision
- dexterity
- cognitive load
- reading level

Desired function and solution recommendations should adapt where possible.

---

# 74. Child-Friendly Journey

For families:

- simple instructions
- visible homes
- reachable zones
- age-appropriate cards
- cooperative participation

Never assign unsafe activities to children.

---

# 75. Older-Adult Journey

Potential priorities:

- safe access
- reduced bending/reaching
- visibility
- trip prevention
- simpler routines

---

# 76. Privacy

Personalization should collect only what is useful.

Home photos, household details, and inventory can be sensitive.

Follow security/privacy policy.

---

# 77. Trust

Trust increases when the system:

- recommends no-cost solutions
- admits uncertainty
- explains recommendations
- does not fabricate reviews
- accurately shows availability
- respects budget
- produces visible results

---

# 78. Friction Budget

Every step in the digital journey has a cost.

Before adding:

- modal
- question
- signup
- tutorial
- permission
- upsell

ask:

> Is this necessary to produce the next customer outcome?

# 79. Progressive Disclosure

Show complexity only when needed.

Begin simple.

- deeper diagnosis
- advanced standards
- inventory
- product ecosystem

# 89. Drop-Off Analysis

2. Is too much information required?

6. Is commerce interrupting progress?
7. Is the diagnosis wrong?

# 116. Journey Maturity Model

## Level 0 — Website

Visitors browse pages and products.

## Level 1 — Guided

Visitors can select a room/problem and receive useful guidance.

## Level 2 — Diagnostic

Desired function and root cause personalize the journey.

## Level 3 — Quest-Based

Visitors complete structured activities and measurable outcomes.

## Level 4 — Adaptive

The system adapts quests, solutions, products, and next actions from customer context and outcomes.

## Level 5 — Whole-Home Operating System

6S Success continuously helps households identify friction, define how spaces should function, complete collaborative improvements, select appropriate solutions, sustain standards, and progressively improve the entire home.

# 117. Non-Negotiable Journey Rules

Claude and subagents must not:

- force commerce before providing value
- require unnecessary personal information
- assume one ideal function for every household
- jump from clutter directly to buying storage
- hide no-cost solutions
- fabricate customer outcomes
- use shame or guilt to drive engagement
- create punitive streaks
- interrupt active quests with excessive upsells
- optimize purchase conversion while reducing quest success
- make physical deck users navigate through generic pages
- lose quest state during checkout when technically avoidable
- scale whole-home complexity before Entryway proves the journey
- call pageviews customer success

# 118. Final Principle

6S Success should not optimize a collection of isolated webpages.

It should optimize a **continuous customer journey from frustration to a visibly better home**.

Every agent should understand the same sequence:

**How did this person arrive?**

**What are they trying to make easier?**

**What does this room or micro-zone need to do for them?**

**What is preventing that today?**

**What outcome would matter?**

**What is the smallest quest that can create progress?**

**Which cards should they complete?**

**Can they solve it with what they already own?**

**If they need something, what solution actually fits?**

**Did the area become easier to use?**

**Can they keep it that way?**

**What should they improve next?**

When the website, decks, app, products, content, SEO/AEO, analytics, and autonomous agents all optimize that same journey, 6S Success becomes more than a content site or store.

It becomes a continuously improving **whole-home operating system for turning household friction into small, achievable, measurable wins.**

That is the purpose of `CUSTOMER-JOURNEY.md`.

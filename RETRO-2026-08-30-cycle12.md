# Retrospective, twelfth cycle ending 2026-08-30

Two commits. Every defect fixed this cycle was one I had introduced myself,
and the largest was invisible because the file looked bigger and therefore
better.

---

## What went well

**Measuring instead of trusting the audit found a bigger problem than the
audit reported.** The report said the zone srcset omitted a variant. Checking
the actual pixel dimensions found that the largest variant was 1024 wide on a
768 wide source: every zone hero was being upscaled by a third, producing a 94
KB file carrying no more detail than the original, offered to wide screens and
used as the social preview for every zone page. It is now 61 KB and every pixel
in it is real.

**The srcset was lying about what it offered.** It advertised 1024w for a file
that is 768 wide, so a browser choosing a candidate by width was told a number
that was not true of the bytes it would receive. Widths are now read from the
files themselves.

**Touch targets were measured, not assumed.** Five control types under 44px,
including the homepage room picker at about 36, which is the control the page
exists for. Scoped to a coarse pointer so the desktop layout is untouched: a
mouse does not need a 44px target, and widening everything for everybody would
change the site to fix a problem only phones have.

**Two form fields would have zoomed iOS and never zoomed back**, leaving a
visitor on a page they have to pan around. `.field input` was already 16px,
which is how I know the rule was understood and these two were simply missed
rather than never considered.

---

## What did not go well

**Every one of these was mine.** The upscaling, the false srcset width, the
unused 320px variant, and the sizes attribute claiming a 680px slot for a
1100px box. All shipped in the cycles where I was moving fast on imagery and
felt productive.

**A bigger file read as a better file.** The 1024 variant looked like the
high quality option in every listing and every diff. Nothing about it said
"this is the same picture, enlarged". The only way to see it was to open the
source and the derivative and compare their dimensions, which I did only
because I was already looking at the srcset for another reason.

**I have now written "measure it rather than trust the report" in four
retrospectives and it keeps paying**, which means I am still not doing it
first. The audit that mentioned the missing variant was four days old. Had I
opened the files then instead of reading the summary, the upscaling would have
gone four days earlier and 110 pages would not have shipped it.

---

## What to change next cycle

**When a report mentions a file, open the file.** Both large findings this
cycle came from doing that, and both were adjacent to, rather than identical
to, what the report said.

**A derivative must never be larger than its source, anywhere.** The room
images got this right by accident, because their sources are 1400 wide and the
tiers stop at 1280. The zone heroes did not. That is a rule worth stating once
rather than rediscovering per pipeline.

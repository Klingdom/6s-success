# Retrospective, seventeenth cycle ending 2026-08-30

Two commits. The sweep I said I would do, which found two more instances, one
of them failing in the opposite direction to all the others.

---

## What went well

**The sweep found what fixing one at a time never would.** Three instances of
"a run that could not look wrote its ignorance over a measurement" had been
fixed across three cycles, all in one file. One grep for every field set to a
not-measured sentinel found two more in under a minute.

**One of them fails the other way, which is why nobody had noticed it.** read()
returns an empty string for a file that is not there, so a missing front matter
document found zero unfilled fields and counted as clean. Every previous
instance produced a false alarm; this one produced a false pass. The class is
not "unknown reported as bad", it is "unknown reported as something", and I had
been holding the narrower version of the rule.

**Proved it by moving the file aside and watching the row change**, then moving
it back. The book row now says YES, NO, or NOT CHECKABLE HERE, and which one it
is rather than collapsing two of them.

**Checked whether the email had gone out before assuming the previous fix
landed.** It has not; the last send predates it. So the corrected report is
still pending rather than delivered, and saying that is more useful than
implying the problem is closed.

---

## What did not go well

**I shipped a crash into the shared pipeline.** My deploy carry-forward
referenced _prev before it was loaded. It ran cleanly here because of where the
lines happened to fall in my working copy, and it broke preflight for the cloud
operator, which found and fixed it. I verified the behaviour and never verified
the ordering, in a file where the ordering is the entire mechanism.

**That is the second time this week another session has cleaned up after a
check I wrote.** Both were the same root cause: tested in the state I was in,
not the state it runs in.

---

## What to change next cycle

**Run the thing from a cold start after editing module-level code.** dashboard.py
executes top to bottom at import, so where a line sits is its semantics. A
second run in the same shell would not have caught this; a fresh process
would have.

**The rule is "unknown must be visible", not "unknown must not alarm".** Both
directions are the same defect and I have now seen four of one and one of the
other.

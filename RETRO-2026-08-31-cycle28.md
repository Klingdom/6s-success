# Retrospective, cycle 28 (2026-08-31)

## What this cycle did

Audited **input lists rather than logic**, which was the action item, and it
paid three times.

**`deploy_freshness` now says how far apart the files are.** It reported
"assets/js/data.js differs, live hash vs repo hash" every run for eight days.
True, and useless: a hash says two files are not the same and refuses to say how
far apart, so a whitespace change and a file with 94 percent of its contents
missing read identically. Each stale asset now prints both sizes and the ratio
when it is large. `data.js` reads **"18x smaller live"**, which is yesterday's
catalogue finding stating itself instead of hiding.

**It was also comparing half the site.** Asset references were discovered from
the home page alone, which sees four. Four more are referenced only elsewhere
and were never compared: `quest.js`, `quest-data.js`, `photos.js`, `shop.js`.
`quest.js` is the one that matters, because it drives the only journey a visitor
can finish while payments are dead, and **production is running a version 11 KB
behind this one**. "Production matches this repository" could have been printed
with the Quest arbitrarily out of date.

**Then a gate on the lists themselves, which found a ninth asset immediately.**
Fixing three short lists does not fix the class. `gate_checker_scope` requires
every fingerprinted asset the site references anywhere to be visible from at
least one discovery page. On its first run it found `assets/css/fonts.css`,
referenced by eight pages and by none of the four. Freshness went from comparing
4 assets to 9.

## What went well

**The new gate proved itself on real data.** It failed on a genuine gap and went
silent once closed. Both verdicts, no synthetic fixture needed, which is a
better证 than anything I could have planted.

**Naming the list made it checkable.** `DISCOVERY_PAGES` exists as a constant
rather than inline literals purely so something outside the file can inspect it.
That is the structural half of the fix; widening the list was only the instance.

**The extra fetches are conditional.** Sizes are only fetched for assets that
already differ, so a healthy deploy pays nothing for the better reporting.

## What did not go well

**A heredoc ate backslashes for the sixth time**, turning `b"\r\n"` into a real
newline and a syntax error. Cycle 23 wrote the rule down as a rule, not a
preference: *stop using heredocs for anything containing a backslash.* I did it
anyway, in the same cycle where I congratulated myself for auditing input lists.
Writing a lesson down has now demonstrably not been enough five separate times;
the thing that works is a check, and there is no check for this one.

**"An asset differs" was in front of me for eight days.** `deploy_freshness` has
printed that line on every run since the outage began, and one of those assets
was the entire catalogue. Cycle 27 found the 10-versus-159 gap by a different
route entirely. The report was not wrong, it was just at the wrong resolution,
and I never once asked it to zoom in.

**Nothing here reaches a customer.** Better instruments, same shop, still
unable to take a payment. Worth repeating rather than letting a fourth week of
green retrospectives imply otherwise.

## What to change next cycle

1. **Make the heredoc rule enforceable.** Six instances. Either always write a
   file, or add a check that refuses source containing control bytes before it
   is saved. The repository already has the latter for `ops/`; what it lacks is
   anything stopping the bad write in the first place.

2. **When a checker reports a difference, make it report the magnitude.**
   `deploy_freshness` is fixed. `check_live_links` says "6 links are dead" and
   not how many products those six links represent.

3. **Read the deck cold, as Phil would.** Filed in cycle 22, again in 27, still
   not done. Either do it next cycle or stop writing it down.

# Retrospective, cycle 19 (2026-08-31)

## What this cycle did

Looked at the site. That is the whole headline. I had changed CSS and markup
roughly twenty times in a week and never once rendered a page, and my own
retrospectives had said to fix that for several cycles running.

Four real defects were sitting on phone screens the entire time:

1. `.btn{white-space:nowrap}` made a long label an unshrinkable floor. "See all
   20 rooms and their micro zones" measures 385px inside a 338px row and pushed
   21px off the right of the **home page**.
2. Grid and flex children default to `min-width:auto`, so that floor climbed the
   tree. On **book.html** it dragged `.wrap` to 453px against a 390px screen:
   hero, headline, eyebrow and *both buy rows* sat off the right edge.
3. The book cover carried an inline `max-width:420px`. An inline style outranks
   the stylesheet, so it silently defeated the global `img{max-width:100%}` and
   hung 56px off screen.
4. **invest.html**'s revenue table needs 486px with no scroll container, so the
   whole document scrolled sideways.

Plus `.q-sec` setting a `padding` shorthand on the same element as `.q-wrap`,
overwriting its horizontal 20px, so every Quest section sat flush against both
edges of a phone.

All 23 top-level pages plus a room and a zone page now measure clean at 390px.

## What went well

**The fix was found by measuring, not by reading.** No static gate in this repo
could have found any of the four. Three of them are cascade and layout
interactions that only exist once a browser resolves them.

**The two buy rows on book.html mattered most.** Every one of those defects was
on a page whose job is to take money, and two of them were on the buy buttons
themselves. This is the closest thing to a revenue defect I have fixed that was
not the outage.

**I proved the new gate can fail.** Every page measures clean, which means a
broken probe and a healthy site produce identical output. `test_mobile_overflow`
now builds three fixtures, a 900px block that must be reported, a page that fits
that must be called clean, and a 900px block inside `overflow-x:auto` that is
contained by design and must not be reported, and requires the tool to tell them
apart.

**The redeploy instruction is now verified rather than assumed.** For six days
the report has told Phil to click Redeploy. That rested on an unmeasured claim:
that the links in the repo are themselves active. They are, all 155 of them. Now
`check_live_links` establishes it every run and prints it under the outage line.

## What did not go well

**My measuring tool was broken, and it broke in the direction of false comfort.**
Edge will not open a window narrower than about 492 CSS pixels, so
`--window-size=390` lays the page out at 492 and the screenshot canvas crops the
right-hand 102px away. I read that crop as a text overflow bug on quest.html and
started diagnosing a defect that did not exist. Then the DOM probe I wrote to
check my reading reported "no overflow" on all four pages, because I had written
the instrumented copy into `build/`, which broke every relative stylesheet path.
So it measured an unstyled page and reported clean.

That is the same defect this project has now hit six times: **a run that could
not look wrote its ignorance over a measurement.** It is not enough to know the
pattern. I wrote a fresh instance of it *in the very act of investigating one*.

**I nearly shipped a non-fix and would have called it a partial win.** The first
version of the button rule went into the *first* `@media (max-width:640px)`
block, above the base `.btn` rule. Media queries add no specificity, so `nowrap`
won on source order and labels still did not wrap. The measurement improved,
6 findings down to 2, which reads like progress. It was a rule doing nothing,
with the improvement coming entirely from a different change in the same edit.
A partial improvement is the most expensive kind of wrong, because it buys the
belief that the mechanism works.

Root cause of that one: I located the insertion point with
`s.index(anchor, 300)`, intending "after line 300", but 300 is a *character*
offset, so it matched the first occurrence.

**The outage is unresolved on day six** and I still cannot clear it.

## What to change next cycle

1. **A harness that cannot confirm its own preconditions must refuse to report.**
   `shoot_mobile.py` now aborts if the viewport it got is not the viewport it
   asked for. Every other measuring tool in `ops/` should be audited for the
   same property: freshness, links, image coverage. The rule is not "handle the
   error", it is *never emit a verdict on a measurement you did not take*.

2. **Instrument a page in place, never in a copy elsewhere.** Any probe that
   relocates a file breaks its relative assets and silently measures a different
   document. `shoot_mobile.py` writes its wrapper beside the source for exactly
   this reason.

3. **When a fix is partial, find out which part worked before shipping.** Two
   changes went in together, findings dropped, and I almost accepted the pair.
   Bisect the edit rather than the outcome.

4. **Stop using character offsets as line offsets.** Cheap and stupid; cost a
   silent no-op in a stylesheet.

5. **Render at more than one width.** Everything here was found at 390px. 360px
   and 768px are untested and the tool already takes `--width`.

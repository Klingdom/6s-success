# Retrospective, cycle 21 (2026-08-31)

## What this cycle did

Built the check that last cycle's accident should have made unnecessary, and
found that one of my analysis tools had been lying to me for weeks.

**Every URL we publish is now checked.** `ops/check_urls.py` resolves all 184
sitemap URLs the way nginx actually does, following the same `try_files` order
as the config: the file, then `$uri.html`, then `$uri/index.html`. A directory
with no index is reported under its own name rather than as "missing", because
it answers 403 and the fix is different. It runs statically in preflight with no
network, and CI points it at the running container, so **184 URLs are asked
instead of the thirteen I happened to think of**. CI confirmed: 184 asked, 0
unreachable, all below 400.

**`link_graph_report.py` has been dropping 201 links.** It resolved a target by
appending `.html`, so `href="../zones/"` became `site/zones.html`, did not
exist, and the link was silently discarded. Every directory-form link on the
site was affected. The consequence was that the busiest hub on the site, the
zone index with 201 inbound links, reported as an **orphan with zero**. It also
counted `zones/index.html` as a zone page in one place while excluding it in
another, which is where "resources.html links to 114 of 115 zone pages" came
from. It reaches every zone there is.

## What went well

**I checked the orphan before acting on it.** The report said one page was
orphaned. The tempting move was to go add links to it. Instead I asked which
page, and it was the zone index, and then asked what links to it, and the answer
was 201 pages. Had I trusted the report I would have added redundant links to
the most-linked page on the site and called it an SEO improvement.

That is the second cycle running where the finding was in the measuring tool
rather than in the thing measured. It is worth naming as a habit: **when a
report shows something surprising, verify the report before believing the
world.**

**The live sweep found nothing, and that is worth something.** 184 URLs, all
answering. Combined with the three 403s fixed last cycle, the public surface is
now known-good rather than assumed-good, and the next regression gets caught by
a gate instead of by me stumbling into it.

**The test drives the resolver directly.** Everything resolves right now, so a
working resolver and a broken one produce identical output. `test_check_urls.py`
covers each `try_files` step, a directory with an index and one without, a
proxied path, and a missing sitemap, which must fail rather than pass quietly.

**I recorded why a duplicated CI step is deliberate.** `checks.yml` runs the
test suite even though preflight's `gate_tests` already does. Twice now
`preflight.py` itself has been the broken thing, and a suite that only runs from
inside the file under suspicion cannot testify about it.

## What did not go well

**The link graph defect is old and I have been reading its output for weeks.**
It informs which pages are thin and which are orphaned, which is exactly the
kind of judgement I have been making about internal linking. Every inbound count
it ever printed was understated. I never questioned it because it produced
plausible numbers, and plausible is the hardest kind of wrong to notice.

**The three 403s and this were the same defect in different clothes.** Both are
"a directory URL is not the same as a file path, and something in this
repository forgot". nginx forgot in `try_files`, the link graph forgot when
appending `.html`. I fixed the first last cycle without asking where else the
same assumption lived. **Fixing an instance is not fixing a class**, and I have
now written that sentence in three consecutive retrospectives.

**Docker still will not start locally**, so behavioural verification keeps
happening in CI. That is a safe place for it, since nothing can reach production
without passing, but the loop is slower than it should be: push, wait, read log.

## What to change next cycle

1. **When a defect is found, search for the same assumption elsewhere before
   closing it.** Concretely: after fixing the 403s I should have grepped for
   every place that turns a URL into a path. That single search would have found
   the link graph immediately, instead of a cycle later and by luck.

2. **Audit the remaining analysis tools the same way I audited this one.**
   `link_graph_report`, `audit_catalog`, `check_live_links` and the dashboard
   all convert between URLs, paths and SKUs. Two of the four have now been found
   wrong. The other two have not been checked, and "not checked" is not "fine".

3. **Give each analysis tool a test that proves it can report a problem.** The
   pattern is now established three times over: everything passes, so passing
   proves nothing.
